--*Day 15*-- Day 15 was a refactor of day 14 around the @dataclass decorator. The @dataclasss decorator allows for python to handle the writing of boilerplate code, like __repr__ and __eq__, while simultaneously supporting encapsulation and input validation in a, frankly, simpler way than the @property decorator. Dataclasses are downright magical. With this, I learned how to use fields, default_factory, and a few different types of instantiation. Speaking of default_factory, there is a bug in dataclasses which the default_factory argument band-aids. In dataclasses, the bug is when you instantiate a mutable array or dict, since all attributes are declared as class attr's, any mutation to those containers will effect other instances as well. To fix this, import fields alongside dataclass and declare the argument in the attr definition. Overall, I was able to accomplish the same code as yesterday, with more functionality, in a simpler and more readable way.

--*Day 19*-- Day 19 was about explicit state transitions, which meant learning how to advance a restrict the state of an object through a pipeline using Enum and not StateTranstion. Honestly, this one was pretty easy. As for the question asked in the assignment: The program establishes the rules in a combination of the Enum object and the Order class itself. The Enum object determines what the states should be, but it doesn't provide the transition logic. The Order class, that owns the actual state the object is in, owns the transition and validation logic for the progression through the pipeline/workflow. This feels like the natural place to hold it, since the Order class holds the object and it's related information and actions. I can see the argument for the Enum to hold it, but the Enum is simply supposed to give an exclusive and predefined list of possibilities. Since that is its sole purpose, asking it to do something else violates best practice. The Orders classes sole purpose in life is to manage Order objects and what happens to them. Thereby, the validation of state transitions fits naturally into the Order class. You can see the implementation for Day 19 in the Day 19 folder within this repo.
